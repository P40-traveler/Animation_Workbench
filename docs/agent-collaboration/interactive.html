这是给 Agent 的分步模板，不是一次粘贴就会生图的脚本。先启动本地服务；必须实际生成 PNG 和完整结果 JSON 后，才能执行对应步骤。每张新图都要上传一次。

Agent 在另一台电脑上怎么办？

远端的 127.0.0.1 指向它自己的电脑，无法用这个地址访问你的工作台。本页不提供公网连接向导。

手动交给它任务 JSON 和所需 PNG。让它返回 PNG 与明确的帧对应关系；在你的电脑上传图片，取得本机真实 image_id，完成映射后再提交结果。远端本地路径不能直接放进结果 JSON。

Agent 这一轮应该以什么为依据？

输入内容不会保存到浏览器存储。

你 · 界面操作

保存修订，再创建任务

先保存规格、参考与动作说明，再创建生成任务。工作台保存这一刻的快照，并返回任务 ID。你手动把它交给 Agent。

为什么“下载任务包”里没有 PNG？

界面的“下载任务包”只下载 JSON。里面包含图片信息与本机 URL；它不是含所有图片的压缩包。

CLI 使用 bundle TASK_ID --output runtime/task.json --download-images，才会把 PNG 下载到 JSON 旁边的 task-images 目录。不要漏掉最后一个参数。

Agent 说已经提交，页面还没有候选？

页面没有自动轮询任务结果。

先模拟另一处保存，再提交候选；点击采用，观察旧的“预期当前版本”为什么会得到 409。
旧任务回传可以创建候选。409 的关键是采用请求里的“预期当前版本”已经过期；不是只要候选基于旧版本就永远无法采用。刷新后应重新比较，确认再采用。采用旧基础候选可能让当前工作内容不再包含 v2 的改动，但 v2 历史版本仍在；也可以基于 v2 新建任务。系统不会自动合并。
失败或取消时，应该检查什么？
409：可能是版本预期过期，也可能是任务状态不允许操作。看具体错误说明；不要靠重复点击覆盖。
422：请求或内容检查不通过，例如返工改了未授权像素。根据说明修正输入；候选提交成功本身也不保证之后格式检查通过。
取消：工作台会拒绝已取消任务的回传，但不会自动停止外部生成工具。需要另行通知 Agent 停止，并检查它使用的工具。
真正交付前，再走完这四步
  1. 在“版本”里比较候选，确认后“采用此版本”。采用不等于人工验收。
  2. 在“交付”页“执行格式检查”，修正硬错误；再亲自检查动作、美术与透明边缘。
  3. 确认满意后点“人工验收通过”。正式导出需要格式通过和当前版本已验收。
  4. 取消默认勾选的“草稿导出”，再“预检导出”。固定帧导出若会丢失特效变化，必须读报告并明确接受；也可以改用保留所有变化。
