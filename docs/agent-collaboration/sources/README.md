## 关键说明到来源的映射

- 创建任务不自动调用外部 Agent：S2任务创建仅持久化快照；S6任务面板显示外部执行说明。
- Agent提交后前端不轮询，用户需“刷新 / 重连”：S6的load与任务状态刷新方式；刷新前应处理未保存草稿。
- 使用项目Python，--url为子命令之前的全局参数：S5/S7。
- 网页下载任务包为JSON，CLI --download-images另存图片：S5/S6。
- 图片上传后获得image_id，结果仍需提供frames和base_revision_id：S2/S3/S5。
- repair需要完整帧数组，不能改变顺序/时长/偏移/特效/事件：S2/S4。
- 候选提交不推进当前版本，采用时检查预期版本：S2。
- 格式检查与人工验收分离，正式导出要求人工验收：S2/S4/S6。
- UI默认草稿导出，正式交付需取消勾选；草稿也不能跳过格式硬错误：S6/S2。
- UI导入结果JSON仅提交文件内容，不自动上传PNG；effects/events省略继承、空数组清空：S6/S2/S3。
- 取消任务只拒绝后续提交，不会中断外部工具：S2仅改变任务记录，没有外部进程管理。
- 本机服务只监听127.0.0.1，远程Agent不能直接使用该地址访问用户电脑：S7的启动配置及网络地址语义；不提供未实现的公网代理步骤。

## 教学简化与边界

演练中的v1/v2和模拟候选不对应真实项目数据。结果JSON中的占位字符串不是有效图片ID或任务ID。返工示例必须提示以下载的base_revision.frames为完整模板。身份/美术质量需要人类判断，成功返回HTTP不代表美术完成。

旧任务基于v1、人类当前版本已变v2时，提交仍可创建候选。409对应携带过期expected_current_revision_id的采用请求，并非任何旧候选都永久不能采用。用户刷新后可以明确采用旧基础的候选，也可以基于v2重新发起任务；首版不会自动合并v2与候选的修改。

本页不执行生成，不自动派发任务，不验证账户密钥，不把参考图片中的文字当执行指令。远程文件交接讲解步骤，但不假设产品已有离线ZIP自动导入或公网服务。
