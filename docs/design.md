# 游戏资产工作台：首版设计

状态：2026-10-30，依据用户确认形成的实现基线。后续变更在本文和接口契约中明确记录。

## 已确认的产品边界

用户本人通过前端与外部 Codex 协作，先从零制作单方向角色的待机、攻击及独立特效。采用本地服务加浏览器。这个工程不接续旧工程。前端与后端分别由 GPT-6 Astra、medium 子 agent 实现；风格文件只由前端 agent 阅读，其他参与者不得读取或转述该文件。

首版的价值是把要求、素材、问题和修订放在同一条可追溯流程中，让用户完成实际修整与导出。生成模型不承诺一次成功，工作台不能把格式合格当作美术合格。

## 首版工作流程

1. 新建项目、角色和动作，选择用途明确的参考图。
2. 设置身体标尺、固定画布、pivot、帧数、帧时长、动作描述和事件。
3. 检查规格、提示词及参考是否一致，确认后创建不可变任务快照。
4. 外部 Agent 读取任务及素材，通过接口提交生成结果或修订候选。
5. 工作台完成格式检查。用户预览角色、特效和合成，比较版本，并标记问题。
6. Agent 按帧、图层及区域修订，用户也可以直接修整像素。
7. 复查相邻帧和动作边界，人工验收后导出 PNG 序列、图集及描述信息。

## v0.1 实现范围

必须能够运行：项目和动作管理；参考图上传；规格与任务快照；真实 HTTP Agent 接口及任务包；图片导入；候选提交和采用；版本比较；帧重排；播放、逐帧、循环、洋葱皮、待机攻击连续预览；pivot/地面/网格；角色与前后景特效；问题区域；基本像素编辑；统一缩放的派生版本；确定性检查；两种时间策略的导出；关闭后重新加载保存结果。

基础像素工具包含铅笔、橡皮、吸色、填充、矩形选区、移动、复制粘贴和撤销重做。非整数缩放是有损转换，不能称为自动获得合格像素画。像素编辑针对选中的图片引用，默认不改变其他引用。

内置 AI 在首版保留明确的模块边界，不伪装已经接入的模型。上下文首先由结构化表单及规则组装，未来的语言模型只提出修改建议。生成首先由外部 Agent 执行。小模型视觉质检、自动视觉返工、多方向生成、骨骼绑定、通用插件市场及多用户在线协作进入后续阶段。

为验收提供程序绘制的测试角色与特效，界面明确标注测试素材。它们验证工作台行为，不代表生成模型的质量。密钥文件不读取、不复制、不提交。付费服务未接入时不发起实际模型调用。

## 空间和时间规则

- 画布坐标原点左上，x 向右、y 向下，单位为最终画布像素；pivot 是画布固定参考点。
- 身体目标尺寸以参考姿势为标尺，不要求每一帧的身体包围盒相同。
- 帧素材偏移独立于 pivot。首版动作在固定舞台预览，主动移动的画面位置由素材及偏移表达，不实现引擎 root motion。
- 图片资源不可变。时间轴帧是图片的引用，拥有稳定 ID。F001 等是排序后的显示编号。
- 帧时长采用正整数毫秒；首版只承诺该时间精度，不宣称精确表示所有分数帧率。区间均为左闭右开。
- 特效拥有自己的帧、帧时长和开始时间，在前景或后景播放一次，区间之外透明。首版用拆段或两条特效表示跨越角色的遮挡。
- 事件绑定稳定角色帧 ID 与帧内偏移，重排后跟随对应帧。删除绑定帧必须先处理事件。
- 循环和动作衔接以明确的边界帧检查，不用自动补间掩盖姿势变化。
- 编辑草稿的撤销只影响本地尚未提交的修改。历史回退产生新修订，不擦除历史。

## 版本及协作

每个动作有当前工作版本，生成与返工另建候选版本。所有提交携带基础版本。人工保存及采用候选时检查当前版本是否仍为预期版本；若已变化，返回冲突并保留候选，禁止最后写入覆盖。

问题标记绑定动作、版本、帧、图层和图片局部区域。帧重排不改变标记对象。替换已标记的图片后，相关问题进入待复核，不能自动宣称已解决。任务状态、格式检查结果、人工验收分别记录。

局部修订任务可以限制帧与角色图层的矩形区域。候选提交后检查未授权区域的像素与时间轴结构，越权结果不被采用。首版不自动扩展修改范围。修好局部后仍需复查邻帧。

## 检查与导出

确定性检查覆盖文件解码、尺寸、目标帧数、有效引用、透明像素、时长、事件范围、已知变换越界及局部修改权限。全空角色帧和全不透明图片提供提示；透明与裁切的视觉质量仍需人审。角色和特效的半透明规则不同，不能统一二值化。

保留时间变化的合成导出取角色帧和特效帧边界的并集，允许合成帧数增加。固定帧导出按角色帧起点取样，如果有中途变化或短特效遗漏，先返回明确损失报告，只有用户明确接受后才导出。分层导出保留各自的完整时序。图集首版固定单元格、不裁紧边缘，保证 pivot 定义不变。

导出包包含序列、图集、manifest：画布、pivot、帧序与时长、事件、图层、来源版本及采样方式。导出后回读校验图像、时间与来源。正式导出要求人工验收当前版本；工作预览可另行导出并明确 draft 状态。

## 软件架构

前端 React + TypeScript + Vite + Canvas 2D；后端 Python + FastAPI + Pillow；SQLite 保存结构数据，磁盘保存不可变 PNG。API 是人类前端与 Agent 的共同入口。长任务状态持久化，首版外部 Agent 负责实际生成，服务重启不会删除待处理任务。

内部模块分为资产/版本、任务/上下文、渲染/编辑、规则检查、导入导出。生成、去背景与视觉质检保留适配边界，不提前设计插件市场或微服务。浏览器像素编辑与后端渲染使用一致坐标、整数平移和 alpha 规则，集成时验证预览和导出。

仅监听 127.0.0.1，首版不开放局域网或互联网。前端使用同源 /api（开发时通过 Vite proxy），后端不允许任意来源跨域或任意文件路径。所有文件访问通过图片 ID。图片大小、画布和导出数量设置明确上限，失败返回可读错误。

## 验收阶段

1. 素材基础：创建、导入、保存、重新打开、播放、pivot 和帧重排。
2. 协作闭环：规格确认、读取任务、提交候选、标问题、限域修订、旧版本冲突。
3. 完整修整：特效独立时间、像素工具、统一缩放、人工验收、两种导出及回读。
4. 后续评测：积累真实失败样本，对比人工检查与模型辅助，统计误报/漏检、净人工时间及每个验收动作的总成本，再决定自动返工范围。

本轮以 1—3 的本地 v0.1 为目标；无法完成的功能须在验收记录中逐项说明，不得通过假按钮或未标注的模拟结果充数。第 4 阶段需要真实样本，不能以虚构准确率验收。
